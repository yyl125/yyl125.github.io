提前为 macOS 28 做准备，改了一版 Gridea

2026-11-03 · 9 min read
Small Talk

这是一篇发布于 4 天前的文章，其中的信息可能已经有所发展或是发生改变

这篇文章自豪地完全采用 Gridea for ARM64 进行编辑和发布

这个博客从建立至今，虽然陆陆续续增加了不少功能，也对主题进行了许多修改，但底层使用的博客程序一直都是 Gridea

作为一款静态博客写作客户端，Gridea 的使用方式相当简单。通过 Markdown 编写文章，在本地生成网站，再将生成的文件部署到 GitHub Pages。对于不需要数据库，也不打算引入复杂后台管理系统的个人博客而言，这样的方式已经足够

不过，随着 Apple Silicon 逐渐成为 Mac 的主流架构，以及 macOS 对旧版 Intel 应用的支持进入最后阶段，已经多年没有得到持续维护的 Gridea，也不得不面对一些兼容性问题

于是，趁着还有时间，决定自己动手和 AI 一起修改一版

为什么还是 Gridea

其实这些年并不是没有考虑过更换博客程序

目前已经有不少成熟的静态网站生成工具，无论是功能、性能还是社区活跃程度，都有比 Gridea 更好的选择。甚至社区已经出现了 Gridea Pro 这种完全重写的工具出现，我也在先前写了一篇文章来表明我的观点

我的另一篇文章

但对于这个博客来说，Gridea 依然能够满足绝大多数需求

文章、主题和配置文件都保存在本地，不需要额外维护数据库，也不需要配置复杂的运行环境。主题基于 EJS 构建，想要修改页面样式或者增加一些功能，直接编辑对应的文件即可。这些年，博客增加的动态、观影记录，以及其他一些零零散散的功能，基本都是在现有主题的基础上逐渐完善的

如果现在更换博客程序，不仅需要重新适配主题，还要考虑文章、配置和原有部署流程的迁移。花费不少时间，最终得到的可能仍然是一个与现在差不多的网站

既然原有的方式用得还算顺手，也就没有特别强烈的理由去改变它

从 Intel 到 Apple Silicon

Gridea 最初发布的时候，Apple Silicon 还没有出现

原版 Gridea 基于 Electron 开发，早期提供的 macOS 安装包主要面向 Intel 架构。对于现在使用 Apple Silicon 的 Mac 来说，运行这些旧版本仍然需要依赖 Rosetta 2。虽然目前通过 Rosetta 2 依然能够使用，但这种兼容方式显然不会一直存在

按照 Apple 已经公布的过渡计划，macOS 27 将是最后一个全面支持 Rosetta 2 的主要版本。从 macOS 28 开始，Rosetta 2 将只保留针对部分旧游戏的有限支持。也就是说，对于 Gridea 这样的普通 Intel 应用而言，如果没有原生 ARM64 版本，未来可能就无法继续在新版 macOS 上运行了

当然，现在距离 macOS 28 正式发布还有一段时间，也没有必要等到真的无法运行时才开始处理。这便是这次修改最直接的原因

借助 AI，尝试修改 Gridea

首先需要说明的是，我并不是一名程序员，也没有接受过系统的软件开发训练

虽然这些年因为维护博客，接触过一些 HTML、CSS、JavaScript，以及服务器部署和自动化脚本相关的内容，但基本都停留在根据实际需要查找资料、修改配置和解决问题的程度。对于 Electron 应用的开发、底层依赖管理以及跨架构编译，自然也谈不上熟悉

如果放在几年前，面对 Gridea 这样一个完整的开源项目，大概也只能等待原作者更新，或者寻找其他开发者提供的修改版本

不过，随着生成式 AI 在代码理解和编写方面的能力逐渐提升，情况似乎有了一些变化。例如这次修改 Gridea，很大程度上就是在 AI 的协助下完成的

从阅读原项目的代码结构、分析依赖关系，到调整构建配置、处理编译错误，以及修复修改过程中遇到的问题，都借助了 AI 提供的分析和代码建议。而我主要负责明确修改目标、判断哪些功能需要保留，并在实际运行过程中进行测试，再根据遇到的问题继续调整

整个过程也并不是简单地向 AI 提出一个要求，就能够直接得到可以使用的程序。尤其是对于这样一个已经有些年头的项目，旧版依赖、构建工具和运行环境之间的兼容性问题，往往需要反复尝试才能解决。AI 给出的方案也不一定始终正确，有时解决了一个问题，又会引入新的问题

不过，相比于完全依靠自己阅读文档、理解代码并逐一排查错误，AI 确实降低了参与这类项目修改的门槛。至少对于我这样没有专业开发背景的人来说，原本不太可能独立完成的事情，现在也有了尝试的可能

不只是重新编译

最开始的想法其实很简单：既然原版 Gridea 已经开源，那么能否直接将它编译成适用于 Apple Silicon 的版本？

不过，实际修改起来，并没有想象中那么简单。首先，Gridea 使用的 Electron 及部分底层依赖已经有些年头。对于一个长期没有持续维护的项目来说，旧版本的依赖关系、构建工具以及运行环境，都可能成为重新编译时需要解决的问题

因此，这次除了适配 ARM64 架构，也更新了项目的部分底层依赖，并处理了一些原有问题及修改过程中出现的兼容性问题。相比于单纯生成一个 ARM64 安装包，我更希望它能够尽可能摆脱对旧运行环境的依赖，在新的 macOS 上继续正常使用

不过，这并不意味着要对 Gridea 进行全面重构

原有的文章管理方式、主题系统以及网站生成和部署流程，都是我希望尽量保留的部分。毕竟，这次修改的目的不是重新开发一款博客客户端，而是让原本熟悉的软件能够继续使用。至于界面和功能层面，也没有刻意追求所谓的现代化设计。对于一款主要用来写文章和生成静态网站的工具来说，能够稳定完成原本的工作，比增加更多功能重要得多

决定开源

既然已经完成了修改，最终还是决定将这份 Gridea for ARM64 公开

GitHub

Gridea 本身就是一个开源项目。这些年来能够一直使用它，并且按照自己的需要修改博客主题，很大程度上也是得益于原作者的开放

因此，这次修改仍然基于原项目进行，相关版权与开源许可也会继续保留。同时，也需要说明，这个版本的修改过程大量使用了 AI 辅助，包括部分代码的编写、调整和问题排查。考虑到我并没有专业的软件开发背景，虽然已经尽可能对日常使用的功能进行了测试，但仍然无法保证所有功能和使用场景都不存在问题

这也并不是 Gridea 的官方更新版本，更不意味着我会接手原项目的后续维护

目前主要还是出于个人使用需求，对 Apple Silicon 的支持、底层依赖以及部分兼容性问题进行了调整。对于其他平台，也没有计划进行非常全面的适配和测试

如果你也在使用 Gridea，并且希望继续在 Apple Silicon Mac 上保留原有的写作方式，可以尝试这个版本。项目源码及安装包会通过 GitHub 提供，具体的修改内容和已知问题也会在仓库中说明。遇到问题了，我们也可以一起解决，努力将 Gridea for ARM64 变得更好

写在最后

从最初建立博客到现在，Gridea 已经陪伴了我相当长一段时间

虽然这些年博客的页面和功能发生了不少变化，但写文章、生成网站、同步到 GitHub Pages 的基本流程，几乎没有改变。对于我来说，这样其实也挺好

并不是所有软件都需要不断增加功能，也不是每一次系统升级，都必须以更换工具作为结束

这次修改 Gridea，也让我对 AI 辅助编程有了一些新的认识。它当然不能保证每一段代码都是正确的，也无法代替实际测试和对问题的判断。但至少在一定程度上，让没有专业开发背景的人，也能够尝试理解和修改原本难以接触的软件项目

如果没有 AI 的协助，我大概不会花费时间去研究 Gridea 的底层代码，更不用说尝试更新依赖、解决兼容性问题并重新编译一个可以使用的版本

当然，这并不意味着自己因此就成为了一个专业的开发者。说到底，这次修改并没有什么特别宏大的计划，只是借助现在能够使用的工具，解决一个自己实际遇到的问题

希望到了 macOS 28，甚至更久以后，依然能够打开熟悉的编辑器，写一篇文章，然后像往常一样发布到博客上

仅此而已

Enjoy～
