初见 Gridea

相信很多人知道 Gridea 是因为 Sspai 少数派的 推荐文章。这是一个曾经推荐过 VVebo、Bob 等神仙 App、出品过 Cuto 壁纸以及众多 Apple 生态效率内容的神奇网站

我的相关需求其实非常简单。我想有个能写自己想法或者其它任何东西，并且能最大限度自己管理、再配合符合我审美的网站主题就可以对外发布的东西即可

我并非有很多的专业知识，甚至压根就不是相关从业者。我的真正专业和工作内容，再大家印象里，是可能没什么文化但是工作岗位却是「人们想象中」的完全不累的「好工作」（具体你可以去看本站「关于」页面）

Gridea 在当时很好的满足的基本需求

第一是免费。尽管我已购买或订阅了众多我愿意支持的应用，如 Surge、Netflix 等，但对于一个新领域众多同类软件或App，我起初仍会保持谨慎。因此，「免费」是我首要考虑的一点

第二是与我熟悉的内容搭配的很好。尽管我不是程序员，顶多算是个「数码内容爱好者」，GitHub 仍然是我常看常用的网站。它和 Cloudflare 一样，被很多人称为「赛博福利姬」。GitHub Pages 搭配 Gridea 和一点点基础的网络知识和 Markdown 这一简单的标记语言就能搭建一个简单的个人站点，确确实实是它最初真正吸引我的原因

当时唯一的问题是，官方或GitHub上的开源主题选择并不丰富，至少与 Wordpress、Hexo 等相比，很少能合我眼缘。倒不是没有优点，而是我那时看到什么都想要，总之是个人问题。后来 Gridea 的作者发布了 Rocky 主题，总体符合我的审美，试了很多后，最终还是确定了我的博客主题为 Rocky

填写完配置、测试、发布，很快我就完成了第一次 Git 提交，上线了一篇测试文章。左看右看，十分满意

漫漫折腾路

从那之后，我就开始了使用 Gridea + GitHub Pages 的建站之路

第一次让我折腾许久的，是当时另一篇在 Sspai 少数派出名的项目「b言b语」。对于第一次需要类似 LeanCloud 这种后端（应该是叫这个名字？）的项目，刚开始折腾确实在一些细节上耗了我非常大的功夫。不过好在最后项目还是成功被我「嫁接」在了我的这个个人博客上

只不过后来随着 LeanCloud 不断的拉垮，以及某些相关规则和政策上等的转变（印象里是有的？），加之项目页面设计粗糙，与博客的整体风格不搭，因此我也是首次尝试自己修改前端 CSS，力求项目与网站其它部分至少在设计中更为协调

这便是现在「随想」页面的雏形

后来，随着知识需求增长，我访问和关注了更多作者的博客或内容。看到他们网站上的有趣设计，我会尝试自己动手实现，先找现成方案（我承认我挺懒的），没有就研究实现方法，看能否搬到我的博客上来。虽常因技术能力不足而失败，但至少学到了不少知识。经过多次比较和重试，我的博客终于变成了现在这个样子。它可能不完美，但至少表达了我的想法

而这一切的基础，或者说让我轻松部署的，毫无疑问，始终是 Gridea

Gridea 的现状

这当然不是一篇全是夸赞的软文。下面我们来聊聊 Gridea 的现状

正如 Gridea Pro 的 Readme 里说的那样，Gridea 最初的开源版本已经停止更新近 4 年之久了。虽然很多东西一直都能跑起来，但在如今的环境下，它依然有很多不完美的地方

首先就是 Gridea 的启动速度。我并不十分了解架构等远超出我技术知识储备的内容，但我知道，这可能和站点包含文章数量和相关配置文件的内容有关。在如今的 M 系列 Mac 上，它可以说是我这台 M2 芯片至少看起来运行起来相当耗时的 App，它往往会在 Docker 上弹跳不少次

相比较而言，我也有在 Windows PC 上安装 Gridea 辅以坚果云同步内容，Gridea 在 Windows 上的运行速度反而让我没那么难以接受

Gridea 的作者 @EryouHao 在后期推出了订阅制的 Gridea，并将先前的开源项目 Gridea 更名为 Gridea 开源客户端。它补齐了 Gridea 的一些问题，比如 PWA（Progressive Web App，渐进式网络应用） 以及一些以往需要自己手搓的功能。我也曾经在早鸟体验期间试用了几次，但因为种种原因，最终还是继续选择了 Gridea 开源客户端

Gridea Pro

Gridea Pro 是近期在 GitHub 上开源的以 Gridea 为基础制作的一款静态博客写作客户端，意图延续 Gridea 的核心愿景：让每个人都能零门槛拥有自己的博客

Gridea Pro 还被 @EryouHao 在 X 上提及

看到有人基于 Gridea 之前的开源客户端，开发了一个新的，功能介绍还挺好的。
把记忆一下子拉回了 4 年前

它采用 Go + Wails + Vue 3 构建，我也简单试用了一下。对于我比较在意的启动速度方面，确实是进步明显。但需要注意的是，它终究不是原版的 Gridea，使用 Gridea Pro 会对原有的 Gridea 目录实行不可逆的迁移（当然你可以重开一个文件夹）

Gridea Pro 目前仍在持续更新中，关于其后续的发展我也会持续关注

属于 Apple Silicon 的时代，X86 Mac 应用要何去何从？

随着 Apple 将 Mac 从 Intel 成功带到了 Apple Silicon 的时代，macOS 也即将结束对基于 Intel 的 App 的支持[1]

据 Apple 官方的说法，后续的 macOS 版本会移除 Rosetta 2，仅会对某些依赖基于 Intel 的框架且没有维护过的较低版本的游戏生效

Rosetta 目前适用于搭载 Apple 芯片的任一款 Mac，并且直到即将发布的下一个主要 macOS 版本 — macOS 27 都仍可使用。从使用 macOS 28 的电脑开始，Rosetta 功能将仅适用于某些依赖基于 Intel 的框架且没有维护过的较低版本的游戏

为了获得卓越性能和日后的兼容性，你应更新基于 Intel 的 App、插件、扩展和其他附加组件以适配 Apple 芯片

就连每次启动 X86 Mac 应用，macOS 也会做出提示

每次打开 Gridea 开源客户端时 macOS 的提示

目前还不清楚 Apple 会在未来的 macOS 28 中如何处理旧版的 X86 App
